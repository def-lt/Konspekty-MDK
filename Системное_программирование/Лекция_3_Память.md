# Системное программирование. Лекция 3. Память

**Краткий тезисный конспект**

### 1. Иерархия памяти (пирамида)
- Регистры → Кэш → Оперативная память (DRAM) → Диски / ленты → Виртуальная память → Аллокаторы.
- Чем ниже уровень — тем больше объём и тем медленнее доступ.
- Регистры — самая быстрая память (не виртуальная, общие для всех процессов на ядре, реализованы на триггерах/flip-flop).

### 2. Регистры
- Хранят 1 бит на триггере (обычно 6 транзисторов).
- Не требуют постоянного обновления (в отличие от DRAM).
- Мало и дороги → компромисс: регистров немного, но их достаточно.
- Доступны программисту (RAX, RBX, XMM и т.д.), часть используется только ядром/устройствами.

### 3. Кэш
- Появился из-за разрыва скоростей процессора и памяти.
- Использует **временну́ю** и **пространственную** локальность.
- Разделён на кэш инструкций и кэш данных (на L1).
- Многоуровневый (L1–L3/L4). Чем выше уровень — тем больше и медленнее.
- Реализован на **SRAM**.

**Политики включения:**
- Inclusive — данные верхних уровней есть и в нижних.
- Exclusive — данные уникальны.
- NINE (Not Inclusive Not Exclusive) — гибрид.

**Политики записи:**
- Write-through — сразу пишем в память (медленно).
- Write-back — пишем только при вытеснении (dirty-бит).

**Организация:**
- Cache line = 64 байта.
- Типы ассоциативности: fully-associative, direct-mapped, set-associative (обычно 2-way).
- MESI-протокол когерентности (Modified, Exclusive, Shared, Invalid).

**Важные проблемы:**
- False sharing — разные переменные в одной cache line → постоянные инвалидации. Решение — padding / выравнивание.
- Speculative execution → уязвимость **Meltdown** (чтение памяти ядра через побочный канал по времени доступа к кэшу).

### 4. Оперативная память (DRAM)
- Один транзистор + конденсатор на бит.
- Нужно периодически обновлять (refresh ~ каждые 64 мс).
- Значительно медленнее SRAM.

### 5. Виртуальная память
- Аппаратная трансляция: **MMU**.
- Память делится на страницы (обычно 4 КБ).
- Многоуровневые таблицы страниц (в Linux: PGD → PMD → PTE).
- **TLB** (Translation Lookaside Buffer) — быстрый кэш трансляций (реализован на CAM).
- ASID — чтобы разные процессы не конфликтовали в TLB.
- При промахе TLB → page fault → ядро подгружает запись.

**Особенности ядра:**
- Ядро мапит свою память в адресное пространство каждого процесса (с защитой).
- Из-за этого стал возможен Meltdown.
- Исправление — **KPTI / KAISER** (почти полное разделение адресных пространств ядра и пользователя).

### 6. Аллокаторы (malloc и выше)
- Работают поверх виртуальной памяти.
- Классический malloc: арены → bins по размерам → free-list.
- При `free` пытается объединять соседние свободные блоки (уменьшение фрагментации).
- Более продвинутые: **jemalloc**, **tcmalloc** (меньше конкуренции между потоками за счёт отдельных арен).
- Slab-аллокаторы / memory pools — для часто выделяемых объектов одного типа.
- Важно выравнивать крупные блоки по размеру страницы (меньше нагрузка на TLB).

### 7. Практические выводы для программиста
- Избегать false sharing (padding структур).
- По возможности выделять связанные данные одним большим куском (лучше локальность).
- Подсказки процессору: `__builtin_prefetch`, `__builtin_expect`, `madvise`.
- Системные вызовы `mmap`, `brk`, `alloca` и т.д.
